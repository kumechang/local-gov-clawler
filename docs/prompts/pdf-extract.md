# PDF・ページの本文を読んで、施設・イベント・団体を取り出すプロンプト

保存した本文(`pdf-text` / `page-text` の出力)をClaudeに読ませて、グラウンドゴルフの
**施設・イベント・団体**を表にするためのプロンプト。D-156 / D-164。

## 使い方

1. 自治体ごとに本文を取り出す(1回の入力は1自治体、PDFなら最大10件まで)。

   ```bash
   # PDF
   localgov-crawler pdf-text --keyword grandgolf --routes-file config/survey_sets/weekly_facility.json --code 11221
   # HTMLページ(施設の詳細が規則で取れなかったページなど)
   localgov-crawler page-text --keyword grandgolf --routes-file config/survey_sets/weekly_facility.json --code 11221
   ```
2. 下の「プロンプト」と、取り出した本文をClaudeに渡す。
3. 返ってきたJSONを `data/extract_ai/<keyword>/<自治体コード>.json` に保存する(原本・本文は保存しない)。
4. 別の取り出し結果(規則ベース)と同じ列なので、そのまま合算できる。

## プロンプト

````text
あなたは、日本の自治体のWebサイトから集めた資料(PDFやWebページの本文)を読んで、
「グラウンドゴルフ」に関する情報を表に整理する担当です。

# 入力
自治体1つぶんの本文が、次の形式で複数並びます。
  ===== 都道府県 自治体名 (自治体コード) [種類] 題名
  URL  ページ数=… OCR=あり/なし 文字数=…
  (本文)
- 本文はPDF・Webページをテキストにしたもので、表は1行(セルを " | " でつなぐ)か、
  行がばらばらに並んでいる。レイアウトは崩れていることがある。
- OCR=あり は画像を文字に起こしたもので、誤字が多い(「グラント・コルフ」など)。

# やること
1. 資料ごとに、グラウンドゴルフ(グランドゴルフ・グラウンド・ゴルフ等の表記ゆれ、OCRの誤字を含む)に
   **実際に関係する記述**があるかを判断する。
   - 関係あり: 施設でグラウンドゴルフができる/専用コースがある、大会・教室・体験会がある、
     グラウンドゴルフの団体(協会・クラブ)の紹介、など。
   - 関係なし(スキップ): 計画・方針・議事録・条例の中で一言触れているだけ、備品台帳、
     名簿、他のスポーツの禁止事項の中の言及、など。理由を `skip_reason` に一言で書く。
2. 関係ありの資料から、次の3種類の行を取り出す。
   - facilities: グラウンドゴルフができる場所(施設・コース・広場)
   - events: グラウンドゴルフの大会・教室・体験会・行事(単発も年間予定の1行ずつも)
   - organizations: グラウンドゴルフの団体(協会・連盟・クラブ・同好会)

# 列
facilities:
  facility_name, address, phone, inquiry_dept, inquiry_phone, usage_note(料金・時間・予約・ルール),
  gg_evidence(グラウンドゴルフに関する根拠の原文 80字以内)
events:
  event_name, event_kind(大会/教室/体験会/交流会/複数競技の大会/その他), date_text(原文),
  date_start, date_end(西暦 YYYY-MM-DD。分からなければ空), fiscal_year(年度。西暦の数字),
  period(期間内/期間外/日付不明。期間内=2025-04-01以降), venue, organizer, target(対象),
  fee, entry(申込方法), deadline(締切), contact_dept, contact_phone,
  evidence(原文 80字以内)
organizations:
  org_name, org_kind(協会/連盟/クラブ/同好会/少年団/その他), activity_place, activity_schedule,
  contact_dept, contact_phone, evidence(原文 80字以内)
共通: pdf_url(その行の根拠になった資料のURL), confidence(high/medium/low)

# ルール(必ず守る)
- **本文に書いてあることだけ**を書く。推測・補完・一般知識での補足をしない。分からない列は空にする。
- evidence は本文からの**そのままの引用**にする(要約しない)。引用できないなら、その行は出さない。
- 日付: 令和・平成は西暦にする(令和8年=2026年)。年が書かれていない月日は、資料の発行年・年度から
  分かるときだけ補い、分からなければ date_start は空、period は「日付不明」にする。
  period は date_start(なければ date_end)が 2025-04-01 以降なら「期間内」、前なら「期間外」。
- 年間行事予定の表は、グラウンドゴルフの大会1回につき1行にする。他のスポーツの行は出さない。
- 同じ内容が複数の資料(同じ資料の別URLなど)にあるときは、1行にして、pdf_url に代表を書く。
- 施設の行は、**グラウンドゴルフができると読み取れるものだけ**(専用の名前がある、利用種目に
  グラウンドゴルフがある、大会の会場になっている等)。料金表に並ぶ全施設を出さない。
- 「グラウンドゴルフは禁止」「グラウンドゴルフ以外の使用は禁止」などの否定は、行にしない。
- **個人の連絡先は書かない**。個人の携帯電話・個人のメールアドレス・自宅住所が書かれていたら、
  その列は空にして、note に「個人の連絡先のため省略」と書く。協会・課・施設の代表の連絡先は書いてよい。
- OCRの誤字は、前後の文脈で確実に直せるものだけ直し、直したら confidence を medium 以下にする。
- 表が崩れていて、どの値がどの行のものか確信できないときは、その行を出さず、
  `unsure` に「何が分からないか」を書く。

# 出力
JSONだけを返す(前後に説明を書かない)。形式:

{
  "municipality_code": "…", "municipality_name": "…",
  "documents": [
    {"pdf_url": "…", "title": "…", "relevant": true/false, "skip_reason": "…",
     "doc_kind": "施設案内/料金表/大会要項/年間予定/広報誌/団体紹介/計画/名簿/その他"}
  ],
  "facilities": [ {…列…, "pdf_url": "…", "confidence": "high"} ],
  "events": [ … ],
  "organizations": [ … ],
  "unsure": [ {"pdf_url": "…", "note": "…"} ]
}

出力する前に、次を自分で確認すること:
(1) すべての行の evidence が、本文にそのまま存在する。
(2) 日付の西暦変換と period の判定が合っている。
(3) 個人の連絡先を書いていない。
(4) グラウンドゴルフ以外の行が混ざっていない。
````

## 確認のしかた(最初の試し)

愛知・福井・埼玉の保存済みPDF(88件)で試し、各種類(施設・イベント・団体)から数行ずつを、
URL付きでユーザーに確認してもらってから、全国に広げる。
