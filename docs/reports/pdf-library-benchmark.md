# PDF読み取りライブラリの比較(日本語の自治体PDF)

ユーザー依頼(2026-11-04): 「PDF読み込みライブラリの選定が肝。最近の流行りや、複数のライブラリを試すなど工夫を」。

## 比較の方法
- **対象のPDF**: 自治体のサイトで、グラウンドゴルフのリンクがあったPDF(全国の123自治体から無作為に抽出)45件と、旭川市のスポーツ関連のPDF20件、見逃しの例(旭川市『市内パークゴルフ場』)1件。実際に取得できた **53件**(robots順守・1秒以上の間隔。残りは404・robots不許可・大きすぎなど)。PDFは保存せず、作業用の場所で使った。
- **読み取り器(6つ)**: `pypdf`(今の実装)、`pdfminer.six`、`pdfplumber`(pdfminer.sixを使う)、`pypdfium2`(PDFium)、`PyMuPDF`(MuPDF)、`poppler`の`pdftotext`。1つのPDFで最大30ページ(本番と同じ)。
- **指標**: 読めた文字数、日本語の割合、`(cid:…)` などの文字化け、実行時間、そしてワード(グラウンドゴルフ)の検出。

## 結果
| 読み取り器 | エラー | 文字なし | ワード検出(31件中) | 53件の合計時間 | 文字化け(cid) |
|---|---|---|---|---|---|
| **pypdfium2** | 0 | 4 | **31** | **0.9秒** | 0 |
| **PyMuPDF** | 0 | 4 | **31** | **1.0秒** | 0 |
| pypdf(今まで) | 0 | 4 | 29(熊本市・大館市を見逃す) | 9.9秒 | 0 |
| pdfminer.six | 0 | 5 | 28 | 23.9秒 | 2(厚木市) |
| pdfplumber | 0 | 5 | 28 | 25.7秒 | 2 |
| poppler pdftotext | 0 | 8 | 26 | 1.6秒 | 0 |

- 「ワード検出31件」は、どれかの読み取り器でグラウンドゴルフが見つかったPDFの数。**pypdfium2 と PyMuPDF はそのすべてを見つけた**。他は 2〜5件を見逃した。
- 読めた文字数が他の最大の半分未満のPDF: pypdfium2・PyMuPDF は0件、pypdf は1件、pdfminer 2件、poppler 5件。
- **4件(7.5%)は、どの読み取り器でも文字が取れない**(画像だけのPDF)。この分は読み取りの工夫ではなく、OCR(画像から文字を読む)が必要。
- 見逃しの例(旭川市のPDF)は、6つすべてが同じ文字数(1,039文字)で読めた。

## 最近の傾向(調べた範囲、ベンダー・コミュニティの比較なので参考)
- 2026年の比較記事・ベンチマークでは、速さと精度の面で **PyMuPDF と pypdfium2** が上位、**pdfminer.six は安定だが遅い**、pypdf は基本の取り出し向け、という評価が多い。コミュニティの比較は、PyMuPDF → pdfplumber → pypdf → pdfminer.six の順に試す『フォールバック』を勧めている。
- ライセンス: PyMuPDF は AGPL-3.0(公開するプロジェクトでも、配布・利用の条件がつく)。pypdfium2 は Apache-2.0 / BSD-3(PDFiumはBSD)で、制約が少ない。
- 日本語では、埋め込みフォントの CMap 不足による文字化け(`(cid:…)`)と、座標の並べ替えによる行順の乱れが典型的な問題。今回の試験でも pdfminer 系だけで cid が出た。
- 新しい選択肢(PDF Oxide、Docling、MinerU、marker など)は、レイアウト・表の読み取りに強いが、重い・AIモデルが必要・ベンダーの数字、という点で、今の『ワードがあるかを見つける』用途には過剰。**表から施設の詳細を取る段階(次の段階)で、別に比較する**。

## 判断(D-147)
1. **既定の読み取り器を `pypdfium2` にする**。速く(pypdfの約10倍)、検出も最多で、ライセンスの制約が少ない。
2. **フォールバックは `pypdf`**(pypdfium2 が読めない・文字が取れないときだけ)。どちらも無ければ `no_reader`。
3. **PyMuPDF は採用しない**(性能は pypdfium2 と同じ。AGPLを避ける)。AGPLを許容するなら、切り替えは簡単にできる。
4. **画像だけのPDF(約7.5%)は、OCR を別の段階で試す**。GitHub Actions では `tesseract-ocr` と日本語データ(`tesseract-ocr-jpn`)を入れられる。pypdfium2 で画像にして読む。手元の環境では tesseract を入れられず、試せていない。
5. 北海道の試しは、`pdf1_hokkaido`(pypdf、実行中)と、`pdf2_hokkaido`(pypdfium2)を比べる。

## 限界
- 53件は小さい標本で、グラウンドゴルフのリンクがあったPDFに偏る。北海道の試しで、より大きな標本の比較をする。
- 『ワードの検出』は、同じワードの検出ルール(表記ゆれ込み)で見た。表の構造・行の順序の正しさは比べていない(施設の詳細の取り出しの段階で比べる)。
