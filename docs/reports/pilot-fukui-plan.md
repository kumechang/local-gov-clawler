# 福井県での確認(推奨の順の C): 計画と事前基準

目的: 奈良県で調整したコードが、**別の県でも同じ水準で動くか**を測る。奈良県の自治体サイトの癖に合わせすぎていないかの確認。

## 条件
- **コードは固定**: `main` @ c9d8acd(改善A入り。奈良県の第4回 `actions_direct_v4` と同一のコード)。実行前に変更しない。
- 対象: 福井県の17自治体(市9・町8)。実行の `route` は `actions_direct_v4_fukui`(奈良県の結果と混ざらないように分ける)。
- 正解データ: `data/ground_truth/sports_hub_fukui.csv`。17自治体から乱数(seed=20261017)で選んだ10件(福井市、敦賀市、小浜市、鯖江市、越前市、坂井市、永平寺町、池田町、高浜町、若狭町)。未選択は7件(大野市、勝山市、あわら市、南越前町、越前町、美浜町、おおい町)。
- 福井県の正解は、コードを調整していない**未使用の検証用**。結果は集計値だけ見る。

## 事前基準(結果を見る前に決めておく)
奈良県の検証用2セット合計(第4回): 到達 10/19(53%)、確定の精度 5/8(63%)。これを基準にして、**大きく劣化していないか**を見る。
1. 福井県の到達が **4/10 以上**(奈良県の53%から、誤差を考えて40%まで許容)
2. 福井県の確定の精度が **40% 以上**(奈良県の63%から、同様に許容)。確定が2件以下のときは精度でなく確定して正解の件数も見る
3. どちらかを下回ったら、「奈良県に合わせすぎていた」可能性が高いとみなし、原因の分析に進む(CMSの違い、ラベルの語彙の違いなど)
4. 両方を満たしても、受け入れ基準(暫定8割)には届かない。それは次のD(AI判定)と、候補に入れる力の改善で扱う

## 分析の進め方
- まず集計値で判定する。
- 基準を下回って原因分析が必要なときは、福井県の詳細を見る。**その時点で、見た10件は開発用になる**。見ていない7件のうちから、新しい検証用を作る。
- 基準を満たしたときは、福井県の詳細は見ずに、次(D: AI判定)へ進める。
