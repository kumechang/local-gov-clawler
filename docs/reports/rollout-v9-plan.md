# v9の確認計画と事前基準(結果を見る前に記録)

関連: D-071〜D-074 / 前提: `docs/reports/rollout-v8-result.md`

## 変更点(v8→v9)
**ルール(判定が変わりうる)**
1. 施設名リンクに数えない語を追加: 整備/助成/のです/ですか/でしょうか/ますか
2. 題名に「予約/申込」を含む汎用ページは自動確定しない

**診断(判定には使わない)**
3. `link_samples`: 施設名リンクが0〜1件の専用候補ページの、ページ内リンク文言の先頭15件
4. `breadcrumb`: 取得した候補ページのパンくず
5. `parent_check`: 確定ページ(なければ1位の取得済み専用候補)の1つ上の階層の題名・施設名リンク数・例・本文中の施設語

## 対象と比較
奈良県39・福井県17・愛知県54・大阪府43・島根県19(区を除く)= 計172自治体。比較は v8 の route(`actions_direct_v8_*`)との差分。

## 事前基準
| # | 項目 | 基準 |
|---|---|---|
| 1 | 意図した変更 | 東大阪市の「公共施設の貸出」(予約ページ)の確定が外れる。河内長野市の施設名リンクから「整備(…助成)」「…のです」が消える |
| 2 | 意図しない確定の変化 | 上記を除く確定の変化は172件中1件以下。変化した件は個別に確認して報告する |
| 3 | 奈良・福井 | 6つの正解データで、到達・確定・正解の件数が v8 と同じ(100%の精度を維持) |
| 4 | 取得面 | 取得失敗0付近。平均リクエスト数は v8 + 1以内(親ページの取得分)。1自治体あたりの容量は平均35KB以下(診断が増える分) |
| 5 | 診断の記録 | 確定した自治体の9割以上で `parent_check` が記録される(親が特定でき、取得または既取得) |

## 診断で確かめること(基準なし。結果を報告し、判定への利用はユーザーに諮る)
- **「1つ上の階層」仮説**: 確定ページの親ページの施設名リンク数が、確定ページより多い自治体は何件か。その親ページは一覧と言えるか。正解が分かっている自治体で試す: 常滑市(正解=体育館の1つ上)、東大阪市(正解は教育委員会配下で、親ページの診断で届くかは不明)、橿原市(奈良県。1つ上が「一覧でないカテゴリ」の例)、あわら市・安堵町(福井・奈良。ユーザーの正解/許容の判断がある例)、川西町(奈良県)。親の方が多い場合に「上へ上がる」規則を入れると、これらが良くなるか悪くなるか
- **取りこぼし6件**(瀬戸・長久手・吉賀・門真・豊明・松原): `link_samples` に何が並んでいるか
- **パンくずの検出率**: 取得した候補ページのうち、`breadcrumb` が取れた割合

## 判断
1〜5を満たせば、診断の集計を報告し、(a)「上の階層へ上がる」規則を入れるか、(b)このまま全国展開に進むかをユーザーに諮る。
