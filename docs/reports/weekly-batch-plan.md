# 全国の週次バッチ — 設計と事前基準(D-154)

2026-11-04 作成。最初の実行の結果は、この基準で判定して報告する。

## 何が動くか

毎週土曜 5:23 JST(`cron: 23 20 * * 5`、UTC金曜20:23。当初は6:00 JSTだったが、毎時0分は遅れるので変更。D-155)に `weekly-batch.yml` が起動し、47都道府県(1,747自治体)について県ごとに次を実行する(同時に動かす県は12まで)。

| 段階 | route | 内容 | 設定 |
|---|---|---|---|
| ① ワード調査 | `weekly_pdf_<県>` | ハブ判定(`redecide_v12_1`)を入口に、PDF+OCRつきで調査 | 上限200ページ・PDF20件・OCR(Tesseract+RapidOCR) |
| ② イベント探索 | `weekly_ev_<県>` | イベント・お知らせ・カレンダーを入口にしたイベント専用の探索 | 上限300ページ |
| ③ 施設の詳細 | `weekly_<県>` | ①で見つかった『場所』のページから 名前・住所・電話・問い合わせ先 | |
| ④ イベントの詳細 | `weekly_<県>` | ①②で見つかった『イベント』のページから 名称・開催日・会場など | |

最後に `report` が全国のCSV(`data/export/weekly/`)とレポート(`data/summary/weekly/latest.md`)を作ってコミットする。

## 時間の見積もり

- ①: 約0.6分/自治体(D-153) × 1,747 ≒ 1,050 runner分。②: 同程度と仮定。各ジョブの準備(Chromium・Tesseract)に約5分 × 約130ジョブ。③④: 小さい。合計 約3,000〜3,500 runner分。
- 同時に動くジョブはGitHubの上限(20)で頭打ち。土曜の午前〜夕方に終わる見込み。最長の鎖は北海道(185自治体・4シャード、約30分/シャード)。
- 公開リポジトリ(D-003)なので無料。

## 既知の限り・注意

- **精度**: PDFだけで見つかる自治体は、計画・名簿・備品台帳の言及が混ざる(D-153。新しい11自治体のうち施設・大会の記述と言えるのは約4〜7件)。今回はPDFの種類で絞っていない。
- **PDFの中の施設・イベントの取り出しは未対応**。PDF由来の行は③④の対象外(HTMLとして取得し直すと意味がないため)。PDFで見つかったページは `survey-export` のCSV(`data/export/weekly/grandgolf_places.csv` など)に出る。
- ワードがあったPDFの本文は `_pdftext/` に保存(D-156)。取り出しは `pdf-text`、一覧は `data/export/weekly/grandgolf_pdfs.csv`。
- 北海道は含める(D-150の打ち切りは『見逃しの調査』のこと)。外すなら `config/weekly_batch.json` の prefectures から消す。
- 毎週同じroute名で上書きするため、一度消えたページ(自治体のサイト改修)は、その週の結果から消える。履歴はgitで見られる。
- 定期実行はmainの最新で動く。マージ前は動かない。マージ後すぐ試すなら、Actionsの『weekly-batch』を手動実行(県を1つ指定可)。
- 1回の実行のジョブ数は約700。1つのmatrixの上限(256)は県数47で収まるが、実行全体のジョブ数の上限に当たったら、県を2つのグループに分けて別の実行にする。
- 結果のコミットは県・段階ごとにmainへ押し込む(衝突時は取り込み直して最大10回再試行)。
